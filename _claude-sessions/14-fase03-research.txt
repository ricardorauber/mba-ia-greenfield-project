**Something you should know before deciding:** the brief assumes MinIO runs locally in Docker, but MinIO stopped publishing free Docker images in October 2025. Its GitHub repository is now archived and marked "no longer maintained". I didn't reopen the storage choice; TD-04 only decides where the local image comes from. I recommend pinning the last official image from the Quay mirror (`quay.io/minio/minio`), with the maintained community copy (`pgsty/minio`) as a one-line fallback.

**Main recommendations:**
- **Queue (TD-01):** BullMQ with Redis, which has an official NestJS module and recovers jobs if a worker dies mid-run. `pg-boss`, which stores the queue in PostgreSQL and adds no new service, is a close second.
- **10GB upload (TD-07, TD-08):** the browser uploads the file in parts straight to storage using short-lived signed URLs. It resumes by re-sending only the missing parts, and the API calls never carry the video bytes. A single signed upload isn't an option because S3 caps one upload request at 5 GiB. The API then confirms the upload is complete and queues the processing job.
- **Signed URLs in Docker (TD-05):** a URL signed for `minio:9000` won't resolve in the browser. The fix is two settings: `S3_ENDPOINT` (the service name) for server-side calls, and `S3_PUBLIC_ENDPOINT` (`localhost:9000`) used only when signing browser URLs.
- **Worker (TD-02, TD-11, TD-12):**
  - It runs from the same codebase as the API but as its own Compose service, with FFmpeg installed only in that image.
  - It calls `ffprobe`/`ffmpeg` directly; `fluent-ffmpeg` is deprecated.
  - It reads only the parts of the file it needs over a signed URL instead of downloading up to 10GB.
- **Formats (TD-09):** accept only formats browsers can play, checked when the upload starts and again by the worker. This phase only extracts metadata and doesn't convert videos, so other formats would be stored but wouldn't play.
- **Status (TD-10, TD-13):**
  - Track processing (`uploading` → `processing` → `ready`/`failed`) separately from publication (`draft`, which Phase 04 extends).
  - Retry temporary errors with backoff; mark permanent errors as failed straight away.
  - A scheduled cleanup job requeues stuck videos and clears uploads that were never finished.
- **URL and delivery (TD-14, TD-15):**
  - Each video gets a random 11-character ID with a unique constraint in the database, so unlisted videos can't be guessed.
  - Playback and download use short-lived signed links straight from storage, which handles partial requests (206) itself. Downloads add an "attachment" setting to the same kind of link.
